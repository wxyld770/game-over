# 21 点 · 朋友牌桌

一款可在浏览器里联机玩的私人 21 点。支持 2–6 人同桌，也能一人练习。每人从 **1,000 虚拟筹码**开始，每局下注与庄家比牌；有人先达到 **10,000 筹码**时，整场结束。

## 开始玩

需要 Node.js 18 或更新版本。项目只使用 Node.js 内置模块，无需安装依赖。

macOS 上可双击 `开始游戏.command`。终端会持续运行游戏服务，浏览器自动打开 `http://localhost:3000`。关闭终端窗口即可停止服务。

也可以在终端运行：

```sh
cd /Users/yoca-709/game-over
npm start
```

打开页面后输入昵称创建房间，将邀请链接或六位房间码发给朋友。和运行服务的电脑处于**同一 Wi-Fi／局域网**的设备可以直接加入；如果 macOS 防火墙询问是否允许 Node 接收入站连接，请允许同一网络设备访问。房间最多六人。单人在房间里也可开始练习。

把代码上传到 GitHub 可以保存和分享项目，但 **GitHub Pages 只托管静态页面，不能运行联机房间所需的 Node 服务**。跨网络联机需要把此 Node 项目部署到能持续运行的服务器。本地同网联机可直接玩。

## 完整规则

### 1. 目标与本金

- 开场时，每位玩家都有 **1,000 虚拟筹码**。
- 整场没有固定局数。每局都与庄家单独结算，并累计各自的筹码。
- 某局结算后，只要有人达到 **10,000 筹码**，整场立即结束。同局多人达标时，结算后筹码最多者获胜；最高额并列则共享冠军。若全员筹码归零，整场结束且无人获胜。
- 筹码归零的玩家只能旁观，直到房主开始新挑战。新挑战会将所有人的本金重置为 1,000。

### 2. 下注与发牌

- 每局开始先下注。下注额必须是整数，且不能超过自己当前的本金。
- 最低下注额为 **50 筹码**；本金不足 50 时，必须全押剩余本金。
- 下注限时 **30 秒**。到时仍在线但未下注的玩家会自动押最低额；离线超过 30 秒的玩家本局旁观，不会被扣筹码。所有下注玩家完成后会立即发牌。
- 每位下注玩家起手拿两张牌。庄家也拿两张，一张明牌、一张暗牌。使用六副牌组成的牌靴，余牌不足时重新洗牌。
- 进行中加入房间的玩家从**下一局**开始参与。

### 3. 牌点与玩家操作

- 2–10 按牌面计点；J、Q、K 各算 10 点；A 可算 1 或 11 点，系统自动采用不爆牌的较高点数。
- 起手**两张**牌正好 21 点称为「自然 Blackjack」，有专门的结算规则。三张或更多牌凑到 21 点不算自然 Blackjack。
- 你可以「要牌」再拿一张，或「停牌」保留当前点数。超过 21 点就是爆牌；拿到 21 点会自动停牌。
- 只有手里仍是起手两张牌时可以「加倍」：本局下注额翻倍，只再拿**一张**牌，然后自动停牌。本金必须足够覆盖翻倍后的赌注。
- 所有玩家同时决策，操作限时 **75 秒**；到时仍未停牌者自动停牌。

### 4. 庄家行动与胜负

- 所有玩家结束操作后，庄家亮出暗牌。庄家低于 17 点继续要牌，达到 17 点或以上停牌；含可按 11 点计算的 A 的「软 17」也停牌。
- 玩家爆牌直接输。庄家爆牌、玩家未爆牌时玩家赢。双方都未爆牌时，玩家点数高于庄家为赢，低于庄家为输，相同为平局。
- 自然 Blackjack 胜过庄家用三张或更多牌组成的普通 21 点；双方都是自然 Blackjack 则平局。庄家的自然 Blackjack 胜过玩家用三张或更多牌组成的普通 21 点。

### 5. 筹码结算

| 本局结果 | 对本金的净变化 |
| --- | ---: |
| 普通获胜 | 赢得下注额的 1 倍 |
| 自然 Blackjack 获胜 | 赢得下注额的 1.5 倍，向下取整 |
| 平局 | 退回下注，净变化 0 |
| 失败或爆牌 | 失去下注额 |

页面的「当前本金」在本局结束时按净赢亏更新。游戏不提供分牌、保险或投降。

整场结束时会先展示最后一局双方的手牌、牌点和结算原因。看完后可进入最终排名，也能从排名页回看最后一局。

**筹码仅供娱乐，不是真实货币，不能购买、提现或兑换。**

## 运行与数据

房间、筹码和牌局暂存在服务进程内存中；关闭或重启服务后会清空。页面会保存本机使用过的房间身份，刷新后可重新连接仍在运行的房间。

## CI/CD 与线上部署

`.github/workflows/ci.yml` 在 Pull Request 和 `main` 更新时检查 JavaScript 语法，并运行真实 HTTP 冒烟测试（健康检查、首页、建房、六人加入和满员限制）。只有 `main` 的检查通过后，才会把同一次检查的代码打成带 SHA-256 校验的发布包，上传到服务器并检查线上健康状态。手动运行工作流只执行检查，不部署。

生产服务运行在 `43.108.47.201:8889`，systemd 服务名为 `game-over.service`。发布使用专门的 `game-over-deploy` SSH 账号；GitHub 仓库的 Actions secret `PROD_SSH_PRIVATE_KEY` 存放该账号的私钥。服务器上由 root 安装的 `deploy/deploy-game-over` 脚本负责校验发布包、切换版本和失败回退。服务器 SSH 主机公钥固定在 `deploy/known_hosts`，无需关闭主机身份检查。

修改 `main` 上的应用代码会触发服务重启。**当前房间、牌局和筹码在内存中，重启后会清空**。只修改 CI、文档或测试，且发布包里的应用文件未变时，部署不会重启服务。上线前请先让玩家结束当前牌局。

### 绑定游戏域名

游戏域名使用 `game.5iyeji.xyz`。在阿里云 DNS 的 `5iyeji.xyz` 解析设置中增加一条 **A** 记录：主机记录 `game`，记录值 `43.108.47.201`，TTL 使用默认值。DNS 不填写端口号。

服务器已有 Nginx 和 acme.sh。DNS 生效前，可把 `deploy/nginx-game-http.conf` 安装为 `/etc/nginx/conf.d/game-over.conf` 并执行 `nginx -t && systemctl reload nginx`。DNS 生效后，用服务器现有的 ACME webroot `/var/www/acme` 为 `game.5iyeji.xyz` 签发证书；用 acme.sh 将证书安装到 `/etc/nginx/ssl/game.5iyeji.xyz/` 并设置续期后重载 Nginx。最后把 `deploy/nginx-game-https.conf` 安装为 `/etc/nginx/conf.d/game-over.conf`，再次运行 `nginx -t && systemctl reload nginx`。HTTPS 配置为游戏的 SSE 实时事件关闭代理缓冲，避免消息延迟。
