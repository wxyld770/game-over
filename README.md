# GAME OVER · 小游戏大厅

打开 [game.5iyeji.xyz](https://game.5iyeji.xyz/) 选择游戏，无需注册或下载。可以和朋友联机玩 21 点、斗地主，也可以自己玩数独、扫雷、蜘蛛纸牌、跳一跳和消消乐。

| 游戏 | 玩法 |
| --- | --- |
| 21 点 | 创建私人房间，1–6 人下注与庄家比牌 |
| 斗地主 | 单人和两名电脑玩，或三人在线同桌 |
| 数独 | 三档难度，支持笔记、提示、撤销与刷新续玩 |

| 消消乐 | 点击或滑动交换相邻宝石；消除后宝石按重力下落、不补新宝石，目标是清空整盘 |

## 开始玩

首页是游戏大厅。选择「21 点」后，输入昵称创建房间，将邀请链接或六位房间码发给朋友；房间最多六人。单人在房间里也能开始游戏。原有的 `/?room=房间码` 链接格式仍可打开 21 点页面，前提是该房间尚未过期。

本地运行需要 Node.js 18.19 或更新版本。首次运行先安装依赖；macOS 上安装完成后可双击 `开始游戏.command`，或在终端运行：

```sh
cd game-over
npm ci
npm start
```

本地游戏大厅默认位于 `http://localhost:3000`。同一局域网的设备可以连接运行服务的电脑；macOS 防火墙提示时，允许 Node 接收入站连接。

## 21 点完整规则

### 1. 本金与整场目标

- 每次开始新挑战，所有玩家各有 **1,000 虚拟筹码**。筹码只在各局结束后按净赢亏更新。
- **目标模式**：开局设定获胜目标，可设为 **1,001–1,000,000 筹码**，默认 10,000。某局结算后有人达到目标，整场结束。同局多人达标时，筹码最多者获胜；最高额相同则共享冠军。多人游戏若只剩一人有筹码，也会提前结束，避免牌局无法继续。
- **无尽模式**：从开局起整场计时 **10 分钟**。到时按筹码排名结算，最高者获胜；最高额相同则共享冠军。多人游戏若此前只剩一人有筹码，则提前结束并由该玩家获胜。单人游戏输光筹码时结束。
- 玩家筹码归零后只能旁观本场。新挑战会把所有人的本金重新设为 1,000。

### 2. 下注与发牌

- 每局先下注。下注额必须是整数，不得超过当前本金。最低下注 **50 筹码**；本金不足 50 时只能全押剩余筹码。快捷选项按当前本金提供最低额、1/4、1/3、1/2 和全押；比例金额向下取整，低于最低下注额时不可选。
- 下注限时 **15 秒**。到时仍在线但未下注的玩家会自动押最低额；离线玩家本局旁观，不扣筹码。所有需要下注的玩家完成后会进入发牌动画。
- 每位下注玩家起手两张牌。庄家也拿两张牌，一张明牌、一张暗牌。发牌期间暂不能操作，动画结束后才开始玩家的 15 秒操作倒计时。
- 使用六副牌组成的牌靴，余牌不足时重新洗牌。进行中加入房间的玩家从下一局开始参与。

### 3. 牌点与玩家操作

- 2–10 按牌面计点；J、Q、K 各算 10 点；A 可算 1 或 11 点，系统自动采用不爆牌的较高点数。
- 起手**两张**牌正好 21 点称为「自然 Blackjack」。三张或更多牌凑到 21 点不算自然 Blackjack。
- 「要牌」再拿一张；「停牌」保留当前点数。超过 21 点即爆牌；拿到 21 点自动停牌。
- 仅在仍持有起手两张牌且本金足够时可「加倍」。点击一次就会将本局下注额翻倍，并立即再拿**一张**牌，然后自动停牌；加倍后不能继续要牌或撤回。
- 所有玩家同时操作，各有 **15 秒**倒计时。普通手牌到时未操作则自动停牌。

### 4. 庄家行动与胜负

- 所有玩家结束操作后，先停顿约 **1 秒**，再由庄家翻开暗牌并逐张补牌。庄家低于 17 点继续要牌，达到 17 点或以上停牌；「软 17」（A 按 11 点算时合计 17）也停牌。输赢在庄家行动结束后才显示。
- 玩家爆牌直接输。庄家爆牌、玩家未爆牌则玩家赢。双方都未爆牌时，玩家点数高于庄家为赢，低于庄家为输，相同为平局。
- 自然 Blackjack 胜过庄家用三张或更多牌组成的普通 21 点；双方都是自然 Blackjack 则平局。庄家的自然 Blackjack 胜过玩家用三张或更多牌组成的普通 21 点。

### 5. 筹码结算

| 本局结果 | 对本金的净变化 |
| --- | ---: |
| 普通获胜 | 赢得下注额的 1 倍 |
| 自然 Blackjack 获胜 | 赢得下注额的 1.5 倍，向下取整 |
| 平局 | 失去下注额的一半，奇数筹码向上取整 |
| 失败或爆牌 | 失去全部下注额 |

游戏不提供分牌、保险或投降。**筹码仅供娱乐，不是真实货币，不能购买、提现或兑换。**

### 6. 多人下一局与结束画面

- 每局结算后，会展示庄家与玩家的手牌、牌点和输赢原因。即使有人在本局输光，也先看到这些结果，再进入整场结束画面。
- 尚未结束整场时，每位**在线玩家**都能点击「下一局」表示准备；所有在线玩家准备后自动进入下一局，离线玩家不会阻塞。游戏过程中不需要房主专门推动牌局。
- 整场结束后可以查看最终排名，也能回看最后一局；开启新挑战会重新设置目标与本金。

## 运行与数据

21 点和斗地主的房间、牌局、虚拟筹码或积分暂存在服务进程内存中；关闭或重启服务后会清空。页面会保存本机使用过的房间身份，刷新后可重新连接仍在运行的房间。数独、扫雷、蜘蛛纸牌、跳一跳和消消乐的进度或本机最高纪录保存在当前浏览器中。跳一跳已提交的排行榜成绩由服务端持久保存。

### 跳一跳排行榜

排行榜显示前 20 名和当前浏览器的个人排名。每个浏览器身份保留最高分，同分按达成时间排序；昵称可以重复。身份保存在 HttpOnly Cookie 中，清除 Cookie 或换设备会成为新的身份。服务端使用本局种子和起跳记录重放计算分数，直接提交分数不会被接受。

本地默认将榜单写入 `.data/jump-leaderboard.json`，可用 `JUMP_LEADERBOARD_FILE` 指定路径。systemd 配置了 `StateDirectory` 时，默认写入该目录，切换代码版本不会丢失榜单。未完成的游戏记录保存在进程内存中，服务重启后需要重新开局。

配置 `JUMP_REDIS_URL` 后使用 Redis 保存榜单，例如：

```sh
JUMP_REDIS_URL='redis://:URL_ENCODED_PASSWORD@127.0.0.1:6379/0' npm start
```

将占位密码替换为 URL 编码后的 Redis 密码。生产环境把连接配置放在服务使用的环境文件中。排行榜应使用开启持久化且不会自动淘汰数据的 Redis 实例；默认键为 `game-over:jump:v1:players`。Redis 不可用时，上榜和刷新会提示重试，游戏仍可继续。

每个上榜游戏有效期为 6 小时，最多记录 10,000 次起跳。超过任一上限后本局仍可继续游玩，最高分保留在当前浏览器中；页面会显示本局无法上榜的状态。

### 测试与发布

运行 `npm test` 验证游戏规则和 HTTP 接口。Redis 集成测试使用独立的临时本地 Redis 进程，不连接生产实例；机器安装了 `redis-server` 后会自动执行，也可通过 `JUMP_TEST_REDIS_SERVER` 指定二进制路径。

CI 安装锁定依赖并执行 Redis 集成测试，发布包包含排行榜模块和共享跳跃规则。更新仓库中的部署脚本后，还需同步服务器上的 `/usr/local/sbin/deploy-game-over`；生产服务通过现有环境文件配置 `JUMP_REDIS_URL`。同时同步 `deploy/nginx-game-https.conf` 的 128k 请求体限制，经 `nginx -t` 检查后 reload，确保长局起跳记录可通过代理。
